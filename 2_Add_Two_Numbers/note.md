# 2. Add Two Numbers

<https://leetcode.com/problems/add-two-numbers/>

## step1（まず通す）

l1 も l2 もノードがあるときはわかりやすくて、両方の値と繰り上がりを足して一の位とくり上がりに分けて処理する。両方ともノードを前に進める
片方がNoneの時は繰り上がりとNoneじゃない方だけ足して同じように処理するが、Noneの方はnextがないのでNoneじゃない方だけ進める。
どっちも Noneでも繰り上がりがあったら最後1が入って終わり。

ミス:

- そもそも繰り上がりと一の位で分けずに単に足してしまう
- 片方が None になった後、直後は繰り上がりを考慮して足し算をするがその次からは単に残っているやつを後続に繋いでしまう(繰り上がり→次が9でまた繰り上がり→... みたいなのを処理できていないし、そもそも今回の関数で出力が入力につながっていたら驚くだろう)
- 最後の繰り上がりを忘れて 1 + 9 = 0 みたいにしてしまう

対策:

- 内容としては繰り上がりのある足し算をしなさいということなので、その手順を正確に言えるようにしてからコードを書き始める
- 問題文をちゃんと読み、紙やらに図を書いて状況を整理する
- コードを読んで思った通りの処理をしているかシミュレーションできるように訓練

## step2（整形＆他の人のコードを読む）

- l1, l2 を改めて変数で置き直す意味はない。
- if else が増え過ぎてみづらくなることを懸念して l1, l2 を進める処理を while ループの冒頭で書いたが、三項演算子を使うと if else の部分の行数が多くなり過ぎずにl1, l2 を進める処理を後に書けて良さそう。
  - <https://github.com/h1rosaka/arai60/pull/7/changes>
- 最上位の足し算が繰り上がったときを最後に処理したが、一応 while の条件に足してまとめることもできそう
  - どっちがいい？例外的な処理だと思ったので最後に書いたが、冷静になると単に一連の処理の最後ってだけな気もする。そもそも sum は 3 つの数の和で、それらのうち一つでも 0 じゃなければループの処理をやる、と思えばループに入れる方が自然か
